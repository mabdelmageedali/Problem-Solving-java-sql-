🔍 584. Find Customer Referee
Names of customers referred by id != 2 OR not referred at all
📌 Problem Statement

Find the names of the customer that are either: referred by any customer with id != 2, or not referred by any customer.

Return the result table in any order.

The result format is in the following example.

📋 Example 1 · Input

Customer table:

idnamereferee_id
1Willnull
2Janenull
3Alex2
4Billnull
5Zack1
6Mark2

Output:

name
Will
Jane
Bill
Zack
sql Solution
SELECT name FROM Customer WHERE (referee_id <> 2 OR referee_id IS NULL);
✅ Detailed Explanation
  • We need customers whose referee_id is not 2 (including null values, because "not referred by any customer" means referee_id is null).
  • Condition referee_id <> 2 would exclude NULLs because NULL comparisons yield UNKNOWN. So we add referee_id IS NULL.
  • Row-by-row analysis:
    • Will (referee_id = null) → matches IS NULL ✅
    • Jane (referee_id = null) → matches IS NULL ✅
    • Alex (referee_id = 2) → <> 2 is false, IS NULL is false ❌
    • Bill (referee_id = null) → matches IS NULL ✅
    • Zack (referee_id = 1) → <> 2 is true ✅
    • Mark (referee_id = 2) → <> 2 is false, IS NULL is false ❌
  • Result: Will, Jane, Bill, Zack — exactly the expected output.
⚠️ Common mistake

Writing referee_id != 2 alone silently drops rows where referee_id is NULL. Always handle NULLs explicitly.

🔑 Conclusion

Use OR ... IS NULL to include missing references. The result order is irrelevant.

🔗 175. Combine Two Tables
Report first name, last name, city, state for every person
📌 Problem Statement

Write a solution to report the first name, last name, city, and state of each person in the Person table. If the address of a personId is not present in the Address table, report null instead.

Return the result table in any order.

Person table
personIdlastNamefirstName
1WangAllen
2AliceBob
Address table
addressIdpersonIdcitystate
12New York CityNew York
23LeetcodeCalifornia
📋 Output
firstNamelastNamecitystate
AllenWangNullNull
BobAliceNew York CityNew York

Explanation: There is no address in the address table for the personId = 1 so we return null in their city and state. addressId = 1 contains information about the address of personId = 2.

sql Solution
SELECT Person.firstName, Person.lastName, Address.city, Address.state FROM Person LEFT JOIN Address ON Person.personId = Address.personId;
✅ Detailed Explanation
  • LEFT JOIN keeps all rows from Person, even when no matching address exists.
  • For personId = 1 (Allen Wang), no address row matches, so city and state become NULL.
  • For personId = 2 (Bob Alice), address exists → city = "New York City", state = "New York".
  • PersonId = 3 exists in Address but not in Person → not included (LEFT JOIN starts from Person).
  • Output matches the expected format (including Null for missing address).
🔑 Conclusion

LEFT JOIN is the standard way to include all records from one table while optionally pulling matching data from another.

📧 182. Duplicate Emails
Find all duplicate emails in Person table
📌 Problem Statement

Write a solution to report all the duplicate emails. Note that it's guaranteed that the email field is not NULL.

Return the result table in any order.

📋 Example 1 · Input

Person table:

idemail
1a@b.com
2c@d.com
3a@b.com

Output:

Email
a@b.com

Explanation: a@b.com is repeated two times.

sql Solution
SELECT email FROM Person GROUP BY email HAVING COUNT(DISTINCT id) > 1; -- USE HAVING WITH GROUP BY NOT WHERE -- THIS TIME THE ID COLUMN WAS THE PRIMARY KEY BUT IN DIFFERENT SCENARIOS -- YOU MAY HAVE TO FILTER BASED ON NON PK COLUMNS SO YOU MUST USE DISTINCT
✅ Detailed Explanation
  • Group rows by email.
  • Use HAVING COUNT(DISTINCT id) > 1 to find groups with more than one distinct id (i.e., duplicated email).
  • Because id is a primary key, COUNT(DISTINCT id) safely counts distinct occurrences. If the table had no PK, we could use COUNT(*).
  • Group analysis:
    • "a@b.com" → ids 1 and 3 → COUNT(DISTINCT id) = 2 > 1 ✅
    • "c@d.com" → id 2 → COUNT(DISTINCT id) = 1, not > 1 ❌
  • Output: a@b.com appears twice, so it's returned.
⚠️ Note

WHERE cannot filter on aggregate results — that's why HAVING is used after GROUP BY.

🔑 Conclusion

Always use HAVING with aggregate conditions, and consider DISTINCT when counting non‑unique columns.

🛒 183. Customers Who Never Order
Find customers with no orders using LEFT JOIN … IS NULL

Write a solution to find all customers who never order anything.

Return the result table in any order.

Customers table

sql Solution
SELECT C.name AS Customers FROM Customers AS C LEFT JOIN Orders AS O ON C.id = O.customerId WHERE O.id IS NULL;
✅ Detailed Explanation
  • LEFT JOIN keeps all customers, matching orders where possible.
  • Customers with no orders get NULL for all Orders columns.

  • In the example: Henry (2) and Max (4) have no orders → returned.
🔑 Conclusion

Anti-join pattern: LEFT JOIN … WHERE right.id IS NULL is a classic way to find non-matching rows.

💰 577. Employee Bonus
Employees with bonus < 1000 or no bonus
📌 Problem Statement

Write a solution to report the name and bonus amount of each employee who satisfies either of the following:

  • The employee has a bonus less than 1000.
  • The employee did not get any bonus.

Return the result table in any order.

Employee table
empIdnamesupervisorsalary
3Bradnull4000
1John31000
2Dan32000
4Thomas34000
Bonus table
empIdbonus
2500
42000
📋 Output
namebonus
Bradnull
Johnnull
Dan500
sql Solution
SELECT e.name, b.bonus FROM Employee e LEFT JOIN Bonus b ON e.empId = b.empId WHERE b.bonus < 1000 OR b.bonus IS NULL; -- [b.bonus IS NULL] is totally different from b.bonus = NULL
✅ Detailed Explanation
  • LEFT JOIN ensures all employees are considered.
  • Employees with no bonus row get NULL for b.bonus; those with bonus less than 1000 are also included.
  • b.bonus < 1000 is false for NULL, so we explicitly add b.bonus IS NULL.
  • Row-by-row:
    • Brad (empId 3) → no bonus → NULL ✅
    • John (empId 1) → no bonus → NULL ✅
    • Dan (empId 2) → bonus 500 < 1000 ✅
    • Thomas (empId 4) → bonus 2000, not < 1000, not NULL ❌
  • Result: Brad (null), John (null), Dan (500).
⚠️ Crucial

b.bonus = NULL is never true — always use IS NULL.

🔑 Conclusion

Combine LEFT JOIN with IS NULL to include employees without a bonus.

🏆 586. Customer Placing the Largest Number of Orders
Find customer_number with most orders using ORDER BY + LIMIT
📌 Problem Statement

Write a solution to find the customer_number for the customer who has placed the largest number of orders.

The test cases are generated so that exactly one customer will have placed more orders than any other customer.

📋 Example 1 · Input

Orders table:

order_numbercustomer_number
11
22
33
43

Output:

customer_number
3

Explanation: The customer with number 3 has two orders, which is greater than either customer 1 or 2 because each of them only has one order. So the result is customer_number 3.

Follow up: What if more than one customer has the largest number of orders, can you find all the customer_number in this case?

sql Solution
SELECT customer_number FROM Orders GROUP BY customer_number ORDER BY COUNT(*) DESC LIMIT 1;
✅ Detailed Explanation
  • Group by customer_number.
  • Order groups by count of orders descending.
  • LIMIT 1 returns the top customer.
  • Group counts:
    • Customer 1 → 1 order
    • Customer 2 → 1 order
    • Customer 3 → 2 orders ← highest
  • Customer 3 has 2 orders, the highest → returned.
📎 Follow-up solution

If multiple customers tie for the most orders, the above query would return only one of them. To return all, you can use RANK() or a subquery with MAX(COUNT(*)).

🔑 Conclusion

ORDER BY + LIMIT is the simplest ranking approach when a single winner is guaranteed.

🔢 619. Biggest Single Number
Largest number that appears exactly once, or NULL
📌 Problem Statement

A single number is a number that appeared only once in the MyNumbers table.

Find the largest single number. If there is no single number, report null.

Example 1 · Input
num
8
8
3
3
1
4

6

Output: 6

Explanation: The single numbers are 1, 4, 5, and 6. Since 6 is the largest single number, we return it.

Example 2 · Input (no singles)
num
8
8
7
7
3
3
3

Output: null

Explanation: There are no single numbers in the input table so we return null.

sql Solution
SELECT MAX(num) AS num -- max(num) returns null if no value from the subquery FROM ( SELECT num FROM MyNumbers GROUP BY num HAVING COUNT(num) < 2 ORDER BY num DESC LIMIT 1 ) AS num;
✅ Detailed Explanation
  • Subquery finds numbers that appear only once (HAVING COUNT(num) < 2), ordered descending, limit 1 for the largest.
  • Outer MAX(num) returns that number if the subquery produced a row; otherwise returns NULL.
  • Example 1 walkthrough: Group counts → 1:1, 3:2, 4:1, 5:1, 6:1, 8:2. Singles are 1,4,5,6. Subquery ordered desc limit 1 → 6. MAX(6) = 6.
  • Example 2 walkthrough: No number appears once, subquery empty → MAX returns NULL. ✅
  • This cleverly handles the "no single number" case by returning NULL.
🔑 Conclusion

Using an aggregate on a subquery that may be empty guarantees a NULL result — perfect for "or null" requirements.

📋 Output

Explanation: All the users registered in contests 208, 209, and 210. The percentage is 100% and we sort them in the answer table by contest_id in ascending order. Alice and Alex registered in contest 215 and the percentage is ((2/3) * 100) = 66.67%. Bob registered in contest 207 and the percentage is ((1/3) * 100) = 33.33%.

sql Solution
SELECT contest_id, ROUND(COUNT(DISTINCT user_id) / (SELECT COUNT(user_id) FROM Users) * 100, 2) AS percentage FROM Register GROUP BY contest_id ORDER BY percentage DESC, contest_id;
✅ Detailed Explanation
  • Subquery (SELECT COUNT(user_id) FROM Users) gets total unique users (3 in this example).
  • For each contest, count distinct registered users, divide by total, multiply by 100, and round to 2 decimals.
  • Order by percentage descending, then contest_id ascending.
  • Per-contest breakdown:
    • 208 → users 2, 6, 7 → 3/3 × 100 = 100.0
    • 209 → users 2, 6, 7 → 3/3 × 100 = 100.0
    • 210 → users 6, 2, 7 → 3/3 × 100 = 100.0
    • 215 → users 6, 7 → 2/3 × 100 = 66.67
    • 207 → user 2 → 1/3 × 100 = 33.33
  • Sorted by percentage desc, then contest_id asc → 208, 209, 210, 215, 207.
🔑 Conclusion

Combine aggregation with scalar subqueries to compute ratios. Always use DISTINCT if registration might have duplicates.

📚 596. Classes With at Least 5 Students
Find classes having ≥ 5 students
📌 Problem Statement

Write a solution to find all the classes that have at least five students.

Return the result table in any order.

📋 Example 1 · Input

Courses table:

studentclass
AMath
BEnglish
CMath
DBiology
EMath
FComputer
GMath
HMath
IMath

Output:

class
Math

Explanation:

  • Math has 6 students, so we include it.
  • English has 1 student, so we do not include it.
  • Biology has 1 student, so we do not include it.
  • Computer has 1 student, so we do not include it.
sql Solution
SELECT class FROM Courses GROUP BY class HAVING COUNT(class) >= 5;
✅ Detailed Explanation
  • Group by class.
  • HAVING COUNT(class) >= 5 keeps only groups with 5 or more students.
  • Group counts:
    • Math → 6 students ≥ 5 ✅
    • English → 1 ❌
    • Biology → 1 ❌
    • Computer → 1 ❌
  • Only Math is returned.
🔑 Conclusion

GROUP BY + HAVING is the standard pattern for filtering aggregated groups.
